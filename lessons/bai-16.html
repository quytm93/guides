Bài nâng cao — cần nắm async/await (Bài 8). Nhắm iOS 17+ / Swift hiện đại.

Vấn đề

Khi nhiều việc cùng sửa một dữ liệu

Nếu hai tác vụ cùng lúc sửa chung một biến, kết quả có thể sai khó lường — gọi là data race.

var tong = 0

// Task A:  tong += 1
// Task B:  tong += 1   (chạy cùng lúc)
// → có thể ra 1 thay vì 2! 😱

Lỗi này rất khó tái hiện & khó sửa. Swift cho ta công cụ để ngăn từ gốc: actor.

Lời giải

Kho an toàn với actor

actor giống class nhưng tự khoá trạng thái bên trong — mỗi lần chỉ một việc được chạm vào:

actor Dem {
    private var tong = 0

    func them() { tong += 1 }
    func ketQua() -> Int { tong }
}

Swift đảm bảo tong không bao giờ bị hai việc sửa cùng lúc → hết data race, không cần tự khoá thủ công.

Truy cập từ ngoài

Chạm vào actor phải await

let dem = Dem()

await dem.them()          // phải await
let n = await dem.ketQua()  // phải await

Vì có thể phải "xếp hàng" chờ tới lượt, mọi truy cập từ bên ngoài actor đều là await. Bên trong actor thì không cần.

Luồng chính

@MainActor — UI ở đúng chỗ

Mọi thứ chạm UI phải ở luồng chính. @MainActor đánh dấu code luôn chạy ở đó.

@MainActor
func capNhatGiaoDien() { ... }   // luôn ở luồng chính

Tin vui: SwiftUI View và lớp @Observable (Bài 9) đã ở @MainActor sẵn — nên gán vào @State sau await là an toàn.

Thoát cô lập

Khi nào dùng nonisolated

Nếu một hàm không đụng trạng thái được bảo vệ, đánh dấu nonisolated để gọi nó không cần await:

actor Logger {
    let ten: String          // bất biến, an toàn sẵn

    nonisolated func mota() -> String {
        "Logger: \(ten)"       // chỉ đọc thứ bất biến
    }
}

Vì mota() không chạm dữ liệu thay đổi, nó không cần "xếp hàng" → gọi thẳng, không await.

Cho nhanh

Chạy song song

// Tuần tự — chậm
let a = await tai1()
let b = await tai2()

Chờ xong việc 1 mới làm việc 2.

// Song song — nhanh
async let x = tai1()
async let y = tai2()
let (a, b) = await (x, y)

async let phóng hai việc cùng lúc.

Nhiều việc động (số lượng không biết trước)? Dùng withTaskGroup để phóng & gom kết quả.

Nâng cao hơn

Tham số isolated

Truyền thẳng một actor vào hàm để hàm chạy trong cô lập của actor đó — bên trong khỏi cần await:

func tangGap(_ dem: isolated Dem) {
    dem.them()
    dem.them()   // không cần await — đã ở trong actor
}

Khá nâng cao — cứ biết nó tồn tại. Khi cần thao tác nhiều bước trên cùng một actor, đây là cách gọn.

Code hoàn chỉnh

Đếm song song an toàn — chép là chạy ✅

import SwiftUI

actor DemSongSong {
    private var tong = 0
    func them() { tong += 1 }
    func ketQua() -> Int { tong }
}

struct CounterDemo: View {
    @State private var ketQua = 0

    var body: some View {
        VStack(spacing: 16) {
            Text("Tổng: \(ketQua)")
                .font(.largeTitle).bold()
            Button("Chạy 1000 lần song song") {
                Task { ketQua = await chay() }
            }
            .buttonStyle(.borderedProminent)
        }
        .padding()
    }

    func chay() async -> Int {
        let dem = DemSongSong()
        await withTaskGroup(of: Void.self) { nhom in
            for _ in 0..<1000 {
                nhom.addTask { await dem.them() }
            }
        }
        return await dem.ketQua()
    }
}

#Preview {
    CounterDemo()
}

1000 việc tăng cùng lúc, nhưng nhờ actor kết quả luôn đúng 1000. Nếu dùng class thường, con số sẽ sai do data race.

Cùng ôn lại

Những gì bạn đã biết

  • Data race: nhiều việc cùng sửa một dữ liệu → kết quả sai
  • actor tự khoá trạng thái; truy cập từ ngoài phải await
  • @MainActor giữ code ở luồng chính (View & @Observable đã sẵn)
  • nonisolated cho hàm không đụng state thay đổi → khỏi await
  • async let / TaskGroup để chạy nhiều việc song song

Bạn không phải tự quản lý khoá/luồng — Swift kiểm tra an toàn ngay khi biên dịch.
