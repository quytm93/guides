Optionals — có thể có, có thể không

Khái niệm "gây vấp" nhất với người mới — nhưng cũng là siêu năng lực giúp Swift an toàn. Nắm chắc nó, mọi bài sau sẽ dễ thở.

Optional xuất hiện khắp khóa (Bài 5, 8, 9…). Hiểu ở đây = không còn hoang mang về sau.

Vấn đề

Khi giá trị "không có"

Đôi khi một giá trị có thể không tồn tại: ô tên người dùng để trống, tìm không thấy kết quả, đổi chữ "abc" sang số…

let so = Int("abc")   // đổi "abc" thành số? → không được!
// so sẽ là "nil" — nghĩa là "không có giá trị"

Nhiều ngôn ngữ để giá trị "rỗng" gây crash bất ngờ. Swift buộc bạn xử lý trường hợp rỗng ngay từ đầu.

Dấu hỏi

Optional với ?

var ten: String = "An"   // LUÔN phải có chữ
var biet: String?        // CÓ THỂ là chữ, hoặc nil

biet = "iOS"            // có giá trị
biet = nil              // không có gì — hợp lệ

String? (có dấu ?) = "một chiếc hộp có thể trống". String (không ?) thì luôn phải có chữ bên trong.

Vì sao hay

Swift bắt bạn kiểm tra

let biet: String? = "iOS"

// ⚠️ Dùng thẳng → in ra cả lớp "Optional"
print("Học \(biet)")   // Học Optional("iOS") — không phải thứ ta muốn

// ✅ Phải "mở hộp" ra trước khi dùng

Đây là điều kỳ diệu: Swift cảnh báo ngay lúc viết code (và báo lỗi nếu bạn dùng optional ở chỗ cần giá trị chắc chắn) — thay vì để app crash trên máy người dùng. Vì vậy ta nên "mở hộp" trước khi dùng.

Mở khoá an toàn

if let — nếu có thì dùng

let biet: String? = "iOS"

if let mon = biet {
    print("Bạn học \(mon)")   // mon là String (đã có)
} else {
    print("Chưa chọn môn")     // trường hợp nil
}

if let mon = biet: "nếu biet có giá trị, gán vào mon rồi chạy khối trong". Bên trong, mon chắc chắn không nil.

Thoát sớm

guard let — không có thì dừng

func chao(_ ten: String?) {
    guard let ten = ten else {
        print("Không có tên")
        return                  // thoát luôn nếu nil
    }
    print("Xin chào, \(ten)!")   // ten dùng được tới cuối hàm
}

guard let hợp khi muốn "không hợp lệ thì thoát ngay". Bạn đã thấy nó ở Bài 8 (kiểm tra response). Sau guard, biến dùng được ở phần còn lại.

Giá trị dự phòng

Toán tử ??

let ten: String? = nil

let hienThi = ten ?? "Khách"
// ten có giá trị → dùng nó; nil → dùng "Khách"
print(hienThi)   // "Khách"

?? (nil-coalescing) = "nếu nil thì dùng giá trị này thay thế". Cách ngắn gọn nhất để có giá trị mặc định.

Hai thứ nữa

Chuỗi ?. & cảnh báo !

// Optional chaining
let doDai = ten?.count
// ten nil → doDai cũng nil,
// không crash

?. = "nếu có thì đi tiếp, không thì trả nil".

// Force unwrap — NGUY HIỂM
let chac = ten!
// nếu ten nil → app CRASH 💥

! ép mở hộp. Chỉ dùng khi chắc chắn 100% có giá trị.

Người mới: hãy quen if let / guard let / ??. Tránh ! trừ khi thật sự chắc chắn.

Code hoàn chỉnh

Chạy trong Playground ✅

func doiSangSo(_ chu: String) -> String {
    if let so = Int(chu) {
        return "Số hợp lệ: \(so)"
    } else {
        return "\"\(chu)\" không phải số"
    }
}

print(doiSangSo("42"))    // Số hợp lệ: 42
print(doiSangSo("abc"))   // "abc" không phải số

let tuoi: Int? = nil
print("Tuổi: \(tuoi ?? 0)")   // Tuổi: 0

Những gì bạn đã biết

  • nil = "không có giá trị"; Kiểu? = có thể nil
  • Swift bắt bạn xử lý nil lúc viết code (an toàn)
  • if let / guard let để "mở hộp" an toàn
  • ?? cho giá trị mặc định
  • ?. đi tiếp an toàn; ! nguy hiểm — hạn chế

Đây là khái niệm "khó nhằn" nhất. Vượt qua nó, bạn đã qua được rào cản lớn nhất của Swift! 🎉
