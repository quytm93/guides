Định vị

Combine dùng khi nào?

🧠 State thường → @Observable

  • Dữ liệu của màn hình (Bài 9)
  • Đây vẫn là cách mặc định trên iOS 17+

🌊 Luồng sự kiện → Combine

  • Theo thời gian: timer, gõ phím, thông báo
  • Cần debounce, gộp, lọc trùng…

Mẹo: khi cần pipeline phản ứng, @Published cho bạn sẵn một publisher qua dấu $ — đó là lúc dùng ObservableObject + Combine.

Bộ ba cốt lõi

Publisher → Operator → Subscriber

📡

Publisher

Nguồn phát giá trị theo thời gian (vd $query).

🔧

Operator

Biến đổi dòng: map, filter, debounce, removeDuplicates.

🎯

Subscriber

Nơi nhận kết quả cuối: sink hoặc .onReceive.

Hình dung như một dây chuyền: dữ liệu phát ra → đi qua các bộ lọc → tới đích để bạn xử lý.

Triết lý phía sau

Cái này gọi là FRP

Những gì bạn vừa thấy có một cái tên: Functional Reactive Programming — lập trình phản ứng bằng công cụ của lập trình hàm.

🌊

Reactive

Dữ liệu là dòng biến đổi theo thời gian, không phải giá trị tĩnh.

🧮

Functional

Biến đổi dòng bằng hàm thuần: map, filter, debounce…

📝

Khai báo

Bạn mô tả pipeline, thay vì viết callback lồng nhau rối rắm.

Lưu ý nhỏ: về mặt kỹ thuật, Combine theo phong cách Rx ("dòng sự kiện rời rạc") chứ không phải FRP "thuần" học thuật — nhưng giới iOS vẫn quen gọi chung là FRP. @Observable & SwiftUI ("giao diện là hàm của state") cũng mang tinh thần này.

Cầu nối đơn giản

Lắng nghe publisher với .onReceive

Ví dụ một đồng hồ "sống" với Timer.publish:

let dongHo = Timer.publish(every: 1, on: .main, in: .common)
    .autoconnect()

Text("Giây: \(dem)")
    .onReceive(dongHo) { _ in
        dem += 1     // chạy mỗi giây
    }

.onReceive là cách nhẹ nhất để nối một publisher vào View — không cần tự quản lý subscription.

Vấn đề

Ô tìm kiếm gọi API… mỗi ký tự

Người dùng gõ "iphone" = 6 ký tự → nếu mỗi ký tự gọi mạng, ta bắn 6 request liên tiếp. Lãng phí & chậm!

// i → ip → iph → ipho → iphon → iphone
// 😱 6 lần tìm kiếm chỉ để gõ 1 từ

Ta muốn: đợi người dùng ngừng gõ (vd 0.4 giây) rồi mới tìm một lần. Đó chính là debounce.

Lời giải

Pipeline debounce

import Combine

class SearchVM: ObservableObject {
    @Published var query = ""          // $query là publisher
    @Published var ketQua: [String] = []
    private var bag = Set<AnyCancellable>()

    init() {
        $query
            .debounce(for: .seconds(0.4), scheduler: RunLoop.main)
            .removeDuplicates()
            .sink { [weak self] text in
                self?.tim(text)
            }
            .store(in: &bag)
    }
}

debounce đợi 0.4s im lặng mới phát; removeDuplicates bỏ lần lặp; sink nhận kết quả cuối để gọi tim().

Hai bẫy thường gặp

Giữ subscription & chọn luồng

🔗 AnyCancellable

  • Phải .store(in: &bag)
  • Không giữ → subscription chết ngay
  • Dùng [weak self] tránh rò rỉ

🧵 Luồng (thread)

  • Publisher có thể phát ở nền
  • Chạm UI phải ở main
  • .receive(on: RunLoop.main)

Lỗi #1 của người mới: quên store(in:) → "sao pipeline không chạy?". Vì nó đã bị huỷ ngay lập tức. Trong ví dụ của ta, debounce(scheduler: RunLoop.main) đã đưa kết quả về main, nên .sink chạm UI an toàn — không cần thêm .receive(on:).

Chọn đúng công cụ

Combine hay async/await?

⚡️ async/await

  • Lấy dữ liệu một lần (Bài 8)
  • Tải API, đọc file

🌊 Combine

  • Luồng liên tục theo thời gian
  • debounce gõ phím, timer, sự kiện

Đừng dùng Combine cho một cú gọi API đơn lẻ — async/await gọn hơn. Combine toả sáng khi có nhiều sự kiện theo dòng thời gian.

Code hoàn chỉnh

Ô tìm kiếm debounce — chép là chạy ✅

import SwiftUI
import Combine

class SearchVM: ObservableObject {
    @Published var query = ""
    @Published var ketQua: [String] = []
    private var bag = Set<AnyCancellable>()

    init() {
        $query
            .debounce(for: .seconds(0.4), scheduler: RunLoop.main)
            .removeDuplicates()
            .sink { [weak self] text in self?.tim(text) }
            .store(in: &bag)
    }

    func tim(_ text: String) {
        ketQua = text.isEmpty ? [] : ["Kết quả cho '\(text)'"]
    }
}

// View hiển thị thuần — dễ xem trước bằng mock
struct ResultList: View {
    let ketQua: [String]
    var body: some View {
        List(ketQua, id: \.self) { Text($0) }
    }
}

struct SearchView: View {
    @StateObject private var vm = SearchVM()
    var body: some View {
        NavigationStack {
            ResultList(ketQua: vm.ketQua)
                .navigationTitle("Tìm kiếm")
                .searchable(text: $vm.query)
        }
    }
}

#Preview {
    ResultList(ketQua: ["Kết quả mẫu A", "Kết quả mẫu B"])  // 👈 mock
}
