Code di động

Closure là gì?

Một khối code bạn có thể gán vào biến hay truyền vào hàm — như một "việc làm" đóng gói sẵn.

let chao = {
    print("Xin chào!")
}

chao()   // chạy khối code → in "Xin chào!"

Closure giống một hàm không tên. Nó là nền của mọi action, callback, sự kiện trong SwiftUI.

Vỡ lẽ

Vì sao Button { } viết vậy

// Hàm nhận closure làm tham số cuối:
Button("Lưu", action: { luu() })

// Trailing closure — đưa khối ra ngoài ngoặc:
Button("Lưu") { luu() }   // y hệt, gọn hơn

Khi closure là tham số cuối, Swift cho phép viết nó ngoài (). Đó là lý do Button, .task, ForEach… đều có khối { } phía sau.

Kiểu của bạn

Struct — kiểu giá trị

struct DiemSo {
    var mon: String
    var diem: Int
}

var a = DiemSo(mon: "Toán", diem: 9)
var b = a            // SAO CHÉP — b là bản riêng
b.diem = 5
print(a.diem)        // vẫn 9 (a không đổi)

struct được sao chép khi gán. Mỗi bản độc lập. View trong SwiftUI & model ở Bài 7 đều là struct.

Khác biệt cốt lõi

Class — kiểu tham chiếu

class TaiKhoan {
    var ten: String
    init(ten: String) { self.ten = ten }
}

let x = TaiKhoan(ten: "An")
let y = x            // CÙNG TRỎ tới một object
y.ten = "Bình"
print(x.ten)         // "Bình" (x và y là một!)

class được chia sẻ (tham chiếu) — nhiều biến trỏ cùng object. Cần init. Đây là lý do Bài 9/18 dùng class cho ViewModel.

Vì sao quan trọng

Struct vs Class — bộ nhớ & tốc độ

Không chỉ khác cách sao chép — chúng nằm ở vùng nhớ khác nhau, nên tốc độ cũng khác.

📦

Struct · giá trị

Thường nằm ở stack · sao chép khi gán · cấp phát/thu hồi rất nhanh · không cần ARC.

🔗

Class · tham chiếu

Nằm ở heap · chia sẻ tham chiếu · ARC đếm tham chiếu · kế thừa được, linh hoạt.

📌 Mặc định dùng struct (Apple khuyến nghị). Dùng class khi cần chia sẻ trạng thái (ViewModel — Bài 9) hoặc cần identity. Nói gần đúng cho dễ nhớ: thực tế struct chứa kiểu tham chiếu, struct quá lớn, hay bị "bắt" trong closure escaping vẫn có thể lên heap; Array/String dùng Copy-on-Write. Đào sâu ở Bài 18 (ARC).

Hợp đồng

Protocol là gì?

Một "hợp đồng": danh sách những gì một kiểu phải có. Kiểu nào "ký" hợp đồng thì phải đáp ứng.

protocol CoTen {
    var ten: String { get }   // ai conform phải có "ten"
}

struct NguoiDung: CoTen {
    var ten: String          // ✅ đáp ứng hợp đồng
}

Dấu : nghĩa là "tuân theo (conform)". Protocol cho phép nhiều kiểu khác nhau dùng chung một "khuôn".

Vỡ lẽ lần nữa

Những protocol bạn đã gặp

🖼

View

"Tôi mô tả được một giao diện" — mọi màn hình SwiftUI conform View.

🔄

Codable

"Tôi đổi được sang/từ JSON" — Bài 8.

🆔

Identifiable

"Tôi có id để phân biệt" — Bài 7, dùng cho List.

Vậy struct ContentView: View nghĩa là "ContentView ký hợp đồng View". Giờ thì cú pháp quen thuộc đó đã rõ nghĩa!

Code hoàn chỉnh

Ghép tất cả vào SwiftUI ✅

import SwiftUI

// struct + protocol Identifiable (S4 + Bài 7)
struct Mon: Identifiable {
    let id = UUID()
    let ten: String
    let diem: Int
}

struct DiemView: View {
    let dsMon = [
        Mon(ten: "Toán", diem: 9),
        Mon(ten: "Văn", diem: 7),
    ]
    var body: some View {
        List(dsMon) { mon in           // closure (S4)
            Text("\(mon.ten): \(mon.diem)")  // interpolation (S1)
        }
    }
}

#Preview {
    DiemView()
}

Những gì bạn đã biết

  • Closure = khối code truyền đi được; trailing closure → { } sau hàm
  • Struct sao chép (giá trị); Class chia sẻ (tham chiếu)
  • Protocol = hợp đồng; : nghĩa là "conform"
  • View / Codable / Identifiable đều là protocol
  • Giờ cú pháp SwiftUI đã rõ nghĩa, không còn "thần chú"
