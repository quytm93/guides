Vì sao quan trọng

Animation không chỉ để đẹp

👀

Dẫn ánh nhìn

Giúp người dùng hiểu cái gì vừa thay đổi, ở đâu.

💬

Phản hồi

Cho cảm giác app "nghe thấy" thao tác của bạn.

✨

Mượt mà

Chuyển cảnh mềm mại thay vì "nhảy" đột ngột.

Tin vui của SwiftUI: bạn animate sự thay đổi của state, không phải tự vẽ từng khung hình.

Cách 1

Bọc thay đổi trong withAnimation

@State private var to = false

Circle()
    .frame(width: to ? 200 : 100)

Button("Phóng to / thu nhỏ") {
    withAnimation {
        to.toggle()      // đổi state trong đây → tự animate
    }
}

Mọi thay đổi giao diện do state đó gây ra sẽ chuyển động mượt thay vì nhảy phắt.

Cách 2

Gắn .animation(_:value:)

Thay vì bọc chỗ đổi state, gắn thẳng vào view và cho nó "canh" một giá trị:

Circle()
    .frame(width: to ? 200 : 100)
    .animation(.easeInOut, value: to)   // đổi `to` → animate

Khác nhau: withAnimation bọc chỗ đổi state; .animation(_:value:) gắn vào view và tự chạy mỗi khi giá trị đó đổi.

Xuất hiện / biến mất

Hiệu ứng với .transition

@State private var hien = false

VStack {
    if hien {
        Text("Xin chào! 👋")
            .transition(.scale.combined(with: .opacity))
    }
    Button("Hiện / ẩn") {
        withAnimation { hien.toggle() }
    }
}

.transition quyết định view vào/ra thế nào: .opacity, .slide, .scale, .move(edge:). Phải đổi trong withAnimation mới chạy.

Tính cách chuyển động

Đường cong & thời lượng

📏

.linear

Đều đặn, máy móc.

🌊

.easeInOut

Mềm ở đầu & cuối — tự nhiên nhất.

🤸

.spring / .bouncy

Nảy nhẹ như lò xo — rất "đời".

withAnimation(.easeInOut(duration: 0.5)) { ... }
withAnimation(.spring) { ... }

Thêm duration: để chỉnh nhanh/chậm. .spring hợp với thao tác chạm, cho cảm giác phản hồi sống động.

Animate cái gì?

Các thuộc tính hay dùng

Image(systemName: "star.fill")
    .scaleEffect(to ? 1.5 : 1)        // to/nhỏ
    .opacity(to ? 1 : 0.3)            // mờ/rõ
    .rotationEffect(.degrees(to ? 360 : 0)) // xoay
    .offset(y: to ? -20 : 0)            // dịch chuyển

Hầu hết thuộc tính số (kích thước, vị trí, độ mờ, góc xoay, màu) đều animate được. SwiftUI tự nội suy giữa hai giá trị.

Nâng cao

Hiệu ứng "bay" matchedGeometryEffect

Khi một phần tử "biến" từ vị trí/kích thước này sang chỗ khác mượt mà — như ảnh nhỏ phóng to thành ảnh lớn.

@Namespace private var ns

// Cùng id + cùng namespace ở 2 trạng thái
Image("anh")
    .matchedGeometryEffect(id: "anh", in: ns)

Đây là kỹ thuật "hero animation". Hơi nâng cao — cứ biết nó tồn tại, khi cần hiệu ứng chuyển cảnh đẹp thì tìm lại.

Code hoàn chỉnh

Thẻ mở rộng có hiệu ứng — chép là chạy ✅

import SwiftUI

struct ExpandCard: View {
    @State private var moRong = false

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            HStack {
                Text("Chi tiết").font(.headline)
                Spacer()
                Image(systemName: "chevron.down")
                    .rotationEffect(.degrees(moRong ? 180 : 0))
            }
            if moRong {
                Text("Nội dung mở rộng hiện ra thật mượt ✨")
                    .foregroundStyle(.secondary)
                    .transition(.opacity.combined(with: .move(edge: .top)))
            }
        }
        .padding()
        .background(.blue.opacity(0.1), in: .rect(cornerRadius: 16))
        .padding()
        .onTapGesture {
            withAnimation(.spring) { moRong.toggle() }
        }
    }
}

#Preview {
    ExpandCard()
}

Những gì bạn đã biết

  • SwiftUI animate sự thay đổi của state, không vẽ từng khung
  • withAnimation { … } bọc chỗ đổi state
  • .animation(_:value:) gắn vào view, canh một giá trị
  • .transition cho hiệu ứng xuất hiện/biến mất
  • Đường cong (.easeInOut, .spring) + thuộc tính (scaleEffect, opacity, rotationEffect, offset)

Đừng lạm dụng — animation tinh tế, đúng chỗ mới làm app sang. Nhiều quá sẽ rối mắt.
