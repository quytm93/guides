Định dạng dữ liệu

JSON trông như thế nào?

Máy chủ thường trả về JSON — một cách viết dữ liệu dạng "khoá: giá trị", máy đọc dễ:

[
  { "id": 1, "title": "Xin chào iOS" },
  { "id": 2, "title": "Swift thật tuyệt" }
]

Đây là một mảng gồm 2 mục, mỗi mục có id và title. Việc của ta: biến nó thành mảng struct trong Swift.

JSON → Swift

Giải mã với Codable

Cho struct tuân theo Codable với tên thuộc tính khớp khoá JSON:

struct Post: Identifiable, Codable {
    let id: Int
    let title: String
}

Codable giúp Swift tự chuyển JSON ↔ struct. Thêm Identifiable (Bài 7) để đưa thẳng vào List. Tên phải khớp: title ↔ "title".

Vì sao cần?

Việc lâu & vấn đề "đứng hình"

Tải mạng mất vài giây. Nếu app ngồi chờ theo kiểu thường, luồng chính bị chặn → màn hình treo, không cuộn/bấm được.

// Cách cũ: callback lồng nhau 😵
tai { data in
    giaiMa(data) { posts in
        capNhat(posts) { ... }
    }
}

Nhiều tầng lồng nhau ("callback hell") — khó đọc, khó bắt lỗi.

// async/await: đọc từ trên xuống 😌
let data = await tai()
let posts = giaiMa(data)
capNhat(posts)

Phẳng, tuần tự như văn xuôi — mà vẫn không treo app.

Chờ thông minh

async / await là gì?

Tải mạng mất thời gian. async/await cho phép "chờ" kết quả mà app không bị treo — người dùng vẫn cuộn, bấm được.

func taiDuLieu() async {
    // await = "chờ ở đây cho tới khi xong"
    let ket_qua = await layTuMang()
}

async đánh dấu hàm "có thể tạm dừng"; await là điểm chờ kết quả. Mấu chốt: trong lúc await, luồng được giải phóng để làm việc khác (vẽ UI, nhận chạm) → app vẫn mượt thay vì treo.

Cân bằng

Vậy callback còn dùng không?

Có chứ! Closure/callback không hề xấu — bạn đã dùng nó suốt mà không để ý. "Callback hell" chỉ xảy ra khi lồng nhiều việc bất đồng bộ.

✅ Vẫn dùng callback

  • Hành động UI: Button { … }, .onTapGesture { … }
  • Biến đổi đồng bộ: map, filter, sorted(by:)
  • API SwiftUI vốn đầy closure — đó là chuẩn

🔄 Nên đổi sang async/await

  • Chuỗi việc bất đồng bộ lồng nhau
  • vd: tải → giải mã → lưu
  • API cũ trả callback? Bọc bằng withCheckedContinuation

Quy tắc gọn: closure cho việc đồng bộ & sự kiện UI; async/await cho việc bất đồng bộ kéo dài.

Người đưa thư

Tải dữ liệu với URLSession

func taiDuLieu() async {
    let url = URL(string: "https://example.com/posts")!

    do {
        let (data, _) = try await URLSession.shared
            .data(from: url)
        let posts = try JSONDecoder()
            .decode([Post].self, from: data)
    } catch {
        print("Lỗi: \(error)")
    }
}

URLSession.shared.data(from:) tải về data thô; JSONDecoder().decode(...) biến nó thành [Post]. do/catch để bắt lỗi mạng.

Phản hồi có "mã"

Mã trạng thái HTTP phổ biến

Mỗi phản hồi kèm một mã 3 chữ số cho biết yêu cầu thành công hay lỗi gì:

✅

2xx · Thành công

200 OK · 201 Created. Mọi thứ ổn, có dữ liệu trả về.

⚠️

4xx · Lỗi phía bạn

400 Bad Request · 401 Unauthorized · 403 Forbidden · 404 Not Found.

🔥

5xx · Lỗi máy chủ

500 Internal Server Error · 503 Service Unavailable.

Nhớ nhanh: 2xx = ngon, 4xx = bạn gửi sai (sai URL, thiếu đăng nhập…), 5xx = máy chủ gặp sự cố.

Xử lý lỗi

Kiểm tra status code trong Swift

Ép response về HTTPURLResponse để đọc statusCode, rồi chỉ giải mã khi thành công:

let (data, response) = try await URLSession.shared.data(from: url)

guard let http = response as? HTTPURLResponse,
      (200..<300).contains(http.statusCode) else {
    print("Lỗi HTTP: \((response as? HTTPURLResponse)?.statusCode ?? 0)")
    return
}

let posts = try JSONDecoder().decode([Post].self, from: data)

(200..<300) là dải mã thành công. Ngoài dải này → có lỗi, ta dừng lại thay vì cố giải mã dữ liệu hỏng.

Khi nào tải?

Tự tải với .task

Gắn .task vào view — nó chạy ngay khi màn hình xuất hiện:

List(posts) { post in
    Text(post.title)
}
.task {
    await taiDuLieu()   // tải khi mở màn hình
}

.task hiểu được await, rất hợp để nạp dữ liệu lúc đầu. Khác với nút bấm (Bài 3) — cái này tự chạy.

Hiện lên màn hình

Lưu vào @State → giao diện tự cập nhật

@State private var posts: [Post] = []

// Sau khi tải xong, gán vào posts:
posts = try JSONDecoder().decode([Post].self, from: data)
// → List tự vẽ lại với dữ liệu mới ✨

Bắt đầu là mảng rỗng [] (màn hình trống). Tải xong, gán vào @State → SwiftUI tự cập nhật List, đúng như Bài 3.

Code hoàn chỉnh

Chép là chạy ✅

import SwiftUI

struct Post: Identifiable, Codable {
    let id: Int
    let title: String
}

// View hiển thị thuần — dễ xem trước bằng mock
struct PostList: View {
    let posts: [Post]
    var body: some View {
        List(posts) { post in Text(post.title) }
    }
}

// Màn hình gọi mạng rồi đưa dữ liệu cho PostList
struct PostScreen: View {
    @State private var posts: [Post] = []
    var body: some View {
        NavigationStack {
            PostList(posts: posts)
                .navigationTitle("Bài viết")
                .task { await tai() }
        }
    }
    func tai() async {
        let url = URL(string:
            "https://jsonplaceholder.typicode.com/posts")!
        do {
            let (data, response) = try await URLSession.shared.data(from: url)
            guard let http = response as? HTTPURLResponse,
                  (200..<300).contains(http.statusCode) else {
                print("Lỗi HTTP"); return
            }
            posts = try JSONDecoder().decode([Post].self, from: data)
        } catch { print("Lỗi: \(error)") }
    }
}

#Preview {
    PostList(posts: [
        Post(id: 1, title: "Bài mẫu A"),   // 👈 mock data
        Post(id: 2, title: "Bài mẫu B"),
    ])
}
Cùng ôn lại

Những gì bạn đã biết

  • App lấy dữ liệu thật từ API qua request → response (JSON)
  • Codable biến JSON thành struct tự động
  • async/await chờ việc lâu mà không treo app
  • URLSession + JSONDecoder để tải & giải mã
  • Kiểm tra status code (2xx ngon · 4xx sai · 5xx lỗi máy chủ) qua HTTPURLResponse
  • .task tự tải khi mở màn hình; @State để cập nhật UI

Tách view hiển thị riêng để xem trước bằng mock data, không phụ thuộc mạng.
