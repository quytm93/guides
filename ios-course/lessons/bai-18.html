Nền tảng

ARC — Swift tự dọn dẹp

Automatic Reference Counting: Swift đếm số nơi đang giữ một object. Đếm về 0 → object được giải phóng tự động.

class TaiKhoan {
    let ten: String
    init(ten: String) { self.ten = ten }
    deinit { print("\(ten) đã được giải phóng") }
}

deinit chạy đúng lúc object bị dọn. Bạn không gọi free() thủ công như nhiều ngôn ngữ khác.

Mấu chốt

Giá trị vs Tham chiếu

📦 Giá trị — struct / enum

  • Được sao chép khi gán/truyền
  • Không bị ARC đếm → không lo rò rỉ
  • SwiftUI View là struct

🔗 Tham chiếu — class / actor

  • Nhiều nơi cùng trỏ tới một object
  • Bị ARC đếm → có thể rò rỉ
  • vd @Observable ViewModel

Mẹo lớn: ưu tiên struct khi được. Phần lớn SwiftUI là struct nên an toàn sẵn — chỉ cẩn thận với class + closure.

Cái bẫy

Retain cycle — chu trình giữ nhau

Hai object giữ strong lẫn nhau → số đếm không bao giờ về 0 → không được giải phóng = rò rỉ bộ nhớ.

class NguoiDung { var the: The? }
class The      { var chu: NguoiDung? }   // trỏ ngược lại

// A giữ B, B giữ A → cả hai kẹt lại mãi 😱

Hay gặp nhất: closure bắt giữ self, mà self lại giữ closure đó (vd subscription Combine — Bài 12).

Lời giải

Phá vòng với weak / unowned

class The {
    weak var chu: NguoiDung?   // không tăng số đếm
}

weak

  • Có thể thành nil → luôn là Optional
  • Dùng khi đối tượng kia có thể biến mất trước

unowned

  • Không Optional, không tăng đếm
  • Dùng khi chắc chắn nó sống cùng hoặc lâu hơn

Một bên dùng weak/unowned là đủ phá vòng. Người mới: phân vân thì chọn weak cho an toàn.

Quay lại Bài 12

Vì sao có [weak self]

$query
    .debounce(...)
    .sink { [weak self] text in
        self?.tim(text)     // self là Optional ở đây
    }
    .store(in: &bag)

VM giữ subscription, subscription (closure) lại giữ VM → vòng lặp. [weak self] cắt một chiều → không rò rỉ. Đây chính là lý do Bài 12 viết vậy!

Trong SwiftUI

Khi nào thực sự phải lo?

✅

Thường an toàn

View (struct), @State, dữ liệu kiểu giá trị — không cần nghĩ về ARC.

⚠️

Cẩn thận

class/@Observable + closure bắt self (Combine, Task, completion).

🧰

Công cụ

Memory Graph Debugger & Instruments (Leaks) để soi rò rỉ.

Đừng rải [weak self] khắp nơi vì sợ — chỉ cần khi có nguy cơ vòng lặp (closure được lưu lại trong chính object).

Code hoàn chỉnh

Thấy ARC tận mắt — chép là chạy ✅

import SwiftUI

class TaiKhoan {
    let ten: String
    init(ten: String) { self.ten = ten }
    deinit { print("🗑 \(ten) đã được giải phóng") }
}

struct ARCDemo: View {
    var body: some View {
        Button("Tạo & huỷ tài khoản") {
            var tk: TaiKhoan? = TaiKhoan(ten: "An")
            print("Đang dùng: \(tk!.ten)")
            tk = nil      // số đếm về 0 → deinit chạy ngay
        }
    }
}

#Preview {
    ARCDemo()
}

Bấm nút & xem Console: gán nil → in ngay "đã được giải phóng". Đó là ARC làm việc. Nếu có retain cycle, dòng đó sẽ không bao giờ in.

Cùng ôn lại

Những gì bạn đã biết

  • ARC đếm tham chiếu, về 0 thì tự giải phóng (xem qua deinit)
  • struct được copy (an toàn); class/actor mới bị đếm
  • Retain cycle: hai bên giữ strong nhau → rò rỉ
  • weak / unowned phá vòng; weak an toàn hơn
  • [weak self] trong closure được-lưu-lại (Combine, Task)

SwiftUI phần lớn an toàn nhờ struct — chỉ cảnh giác ở class + closure giữ self.
