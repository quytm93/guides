Nền tảng bố cục

Ba "chồng" view

↕️

VStack

Xếp dọc — trên xuống dưới.

↔️

HStack

Xếp ngang — trái sang phải.

🗂

ZStack

Xếp chồng lên nhau — view sau đè lên view trước.

ZStack {
    Color.blue            // nền phía dưới
    Text("Nổi lên trên")   // chữ nằm trên nền
}

Ghép ba loại này lại là bạn dựng được gần như mọi bố cục giao diện.

Cho gọn gàng

Khoảng cách & căn lề

// Khoảng cách giữa các view
VStack(spacing: 16) {
    Text("Dòng 1")
    Text("Dòng 2")
}

spacing = khoảng hở giữa các phần tử.

// Căn lề trái cho cả cột
VStack(alignment: .leading) {
    Text("Tiêu đề")
    Text("Phụ đề")
}

.leading = sát trái, .center = giữa, .trailing = sát phải.

Modifier bố cục

Lề & kích thước

Gắn .padding() và .frame() vào view để tạo khoảng thở và định cỡ:

Text("Xin chào!")
    .padding()                 // lề quanh chữ
    .frame(maxWidth: .infinity)  // rộng hết bề ngang
    .background(.blue.opacity(0.15),
        in: .rect(cornerRadius: 12))  // nền + bo góc

Thứ tự modifier có quan trọng: .padding() trước .background() sẽ cho nền to hơn (bao cả lề).

Vấn đề

Khi có nhiều phần tử?

Gõ tay từng Text cho một danh sách dài thì rất mệt và khó sửa:

VStack {
    Text("🍎 Táo")
    Text("🍌 Chuối")
    Text("🍊 Cam")
    // ... 50 dòng nữa thì sao? 😩
}

Ta cần cách nói: "với mỗi món trong danh sách, hãy tạo một Text". Đó là việc của ForEach.

Lời giải 1

Lặp view với ForEach

let trais = ["🍎 Táo", "🍌 Chuối", "🍊 Cam"]

VStack(alignment: .leading, spacing: 8) {
    ForEach(trais, id: \.self) { trai in
        Text(trai)
    }
}

ForEach chạy qua từng món trong mảng trais, mỗi vòng đưa ra một trai để bạn dựng view. Thêm/bớt món trong mảng → giao diện tự đổi.

Một chút giải thích

id: để làm gì?

SwiftUI cần phân biệt các phần tử để cập nhật đúng chỗ. id là "danh tính" của mỗi phần tử.

✅ Dữ liệu đơn giản

  • Mảng chữ/số → dùng id: \.self
  • Vì mỗi giá trị tự nó là duy nhất

🔜 Dữ liệu phức tạp

  • Mảng các struct → cho nó tuân theo Identifiable
  • Ta sẽ gặp ở các bài sau

Người mới: cứ nhớ "mảng chữ → id: \.self" là đủ dùng cho hôm nay.

Lời giải 2

Danh sách cuộn với List

List giống VStack nhưng cuộn được và có sẵn kiểu dáng đẹp của iOS:

List {
    Text("🍎 Táo")
    Text("🍌 Chuối")
    Text("🍊 Cam")
}

Đây chính là kiểu danh sách bạn thấy ở app Cài đặt, Mail, Danh bạ… của iPhone.

Ghép lại

List + ForEach từ dữ liệu

struct FruitListView: View {
    let trais = ["🍎 Táo", "🍌 Chuối", "🍊 Cam"]

    var body: some View {
        List(trais, id: \.self) { trai in
            Text(trai)
        }
    }
}

List nhận luôn mảng dữ liệu — gọn hơn cả ForEach bên trong. Mỗi món thành một hàng cuộn được.

Hàng đẹp hơn

Mỗi hàng là một bố cục riêng

Bên trong mỗi hàng, bạn tự do dùng HStack, VStack, icon…:

List(trais, id: \.self) { trai in
    HStack {
        Image(systemName: "leaf.fill")
            .foregroundStyle(.green)
        Text(trai)
        Spacer()          // đẩy mọi thứ sang trái
    }
}

Spacer() là "lò xo" chiếm hết chỗ trống — rất hợp để đẩy view về một phía trong HStack.

Cùng ôn lại

Những gì bạn đã biết

  • VStack · HStack · ZStack để xếp view dọc / ngang / chồng
  • spacing, alignment, .padding(), .frame() để chỉnh bố cục
  • ForEach lặp view từ một mảng dữ liệu
  • List tạo danh sách cuộn được, đẹp kiểu iOS
  • Mỗi hàng có thể là một bố cục riêng (HStack + icon + Spacer)

Giờ bạn dựng được những màn hình "thật" hơn nhiều rồi đấy.

Xem trước

#Preview hoạt động thế nào?

#Preview {
    FruitListView()
}
  • Xcode đọc khối #Preview để vẽ Canvas bên phải.
  • Nó tạo một bản của view — FruitListView() — rồi hiển thị ngay, không cần chạy cả app trên Simulator.
  • Sửa code → Canvas cập nhật tức thì: vòng lặp xem trước cực nhanh.
  • Chỉ chạy lúc lập trình; nó không nằm trong app khi phát hành.

Bạn có thể đặt nhiều #Preview trong một file để xem nhiều trường hợp khác nhau.

Dữ liệu giả

Mock data — xem trước bằng dữ liệu mẫu

Khi một view nhận dữ liệu vào, Preview cần "đưa cho nó" một ít dữ liệu. Ta truyền dữ liệu giả (mock) ngay trong #Preview:

struct FruitRow: View {
    let trai: String          // view này cần dữ liệu
    var body: some View {
        HStack {
            Image(systemName: "leaf.fill")
            Text(trai)
        }
    }
}

#Preview {
    FruitRow(trai: "🍎 Táo")   // 👈 dữ liệu giả
}

Mock data = dữ liệu mẫu bịa ra để xem & thiết kế giao diện mà chưa cần dữ liệu thật. Đổi mock để thử nhiều trạng thái: rỗng, 1 mục, nhiều mục…

Code hoàn chỉnh

Chép là chạy ✅

import SwiftUI

// Một hàng — nhận dữ liệu vào qua "trai"
struct FruitRow: View {
    let trai: String
    var body: some View {
        HStack {
            Image(systemName: "leaf.fill")
                .foregroundStyle(.green)
            Text(trai)
            Spacer()
        }
    }
}

struct FruitListView: View {
    let trais = ["🍎 Táo", "🍌 Chuối", "🍊 Cam"]
    var body: some View {
        List(trais, id: \.self) { trai in
            FruitRow(trai: trai)
        }
    }
}

// Hai preview: cả danh sách, và một hàng với mock data
#Preview("Danh sách") {
    FruitListView()
}

#Preview("Một hàng") {
    FruitRow(trai: "🍎 Táo")   // 👈 dữ liệu giả
}

Tách FruitRow ra giúp mỗi hàng tự xem trước được bằng mock data — không cần dựng cả danh sách.
